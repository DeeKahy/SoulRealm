(Topic C: Classes P and NP; closure; P vs. NP; reductions; NP-hardness / NP-completeness)

-------------------------------------------------
1. Class P  
- Definition  
  P = { L ⊆ Σ* | ∃ deterministic Turing machine M and k ∈ ℕ s.t. L(M) = L and M runs in time O(n^k) }.  
  – Equivalent: single-tape, multi-tape or RAM model (polynomial overhead).  
- Examples of languages in P  
  – Regular languages, CFLs, {a^k b^k c^k | k ≥ 0}, DNF-SAT, NNFA, 4CLIQUE, GRAPH-CONNECTIVITY.  
  – ∅ and Σ* are trivially in P.  
- Closure properties  
  – Closed under union, intersection, complement, concatenation, Kleene-star, polynomial-time mapping reductions.  
- Typical polynomial-time algorithms  
  – Breadth-first search, dynamic programming, Gaussian elimination, etc.

-------------------------------------------------
2. Class NP  
- Definition  
  NP = { L ⊆ Σ* | ∃ nondeterministic Turing machine M and k ∈ ℕ s.t. L(M) = L and M runs in time O(n^k) }.  
  – Equivalent: certificate / verifier definition: L ∈ NP ⇔ ∃ poly-time verifier V and polynomial p such that  
    x ∈ L ⇔ ∃ certificate c, |c| ≤ p(|x|), V(x, c) = 1.  
- Examples of languages in NP  
  – SAT, 3-SAT, CLIQUE, VC (Vertex Cover), 3-COLOURING, TSP(D), SUBSET-SUM.  
- Closure properties  
  – Closed under union, intersection, concatenation, polynomial-time mapping reductions.  
  – NOT known to be closed under complement (⇔ NP = co-NP).

-------------------------------------------------
3. “P vs. NP” problem  
- Central open question: Does P = NP?  
  – Intuition: “Can every problem whose solution can be verified quickly (in polynomial time) also be solved quickly?”  
  – Consequences:  
    • If P = NP, all NP problems collapse to P.  
    • If P ≠ NP, there exist problems in NP that have no polynomial-time algorithm.  
- Current evidence  
  – SAT is NP-complete but no polynomial-time algorithm known.  
  – Thousands of NP-complete problems share this fate.

-------------------------------------------------
4. Polynomial-time reductions  
- Definition  
  A ≤p B (A polynomial-time reduces to B) ⇔ ∃ polynomial-time computable function f such that  
  ∀x ∈ Σ*, x ∈ A ⇔ f(x) ∈ B.  
- Usage  
  – Prove A ∈ P: if B ∈ P and A ≤p B, then A ∈ P.  
  – Prove A is NP-hard: if A ≤p B for some NP-hard A, then B is NP-hard.  
- Transitivity  
  – If A ≤p B and B ≤p C, then A ≤p C.

-------------------------------------------------
5. NP-hardness and NP-completeness  
- Definitions  
  – A language L is NP-hard if every language in NP polynomial-time reduces to L.  
  – A language L is NP-complete if it is both in NP and NP-hard.  
- How to show NP-completeness (Cook–Levin paradigm)  
  1. Show L ∈ NP (polynomial-time verifier).  
  2. Show L is NP-hard: pick known NP-complete problem A and give polynomial-time reduction A ≤p L.  
    – SAT ≤p L suffices (since SAT is NP-complete).  
- Typical NP-complete reductions  
  – SAT ≤p 3-SAT (Exercise 2, Tutorial 13).  
  – SAT ≤p VC (Tutorial 12, Exercise 3).  
  – SAT ≤p CLIQUE (standard).  
- Completeness under P = NP (Tutorial 13, Exercise 1.2)  
  – If P = NP, every nontrivial language in NP is NP-complete.  
  – Hence NP-complete problems are dense in NP (under P = NP).

7. Typical exam checklist  
- Can you give a polynomial-time verifier for a new language?  
- Can you design a polynomial-time reduction from SAT (or 3-SAT) to a new problem?  
- Can you argue why a given exponential-time algorithm does NOT prove the problem is not in P?  
- Can you explain why 4CLIQUE ∈ P yet CLIQUE might not be?
