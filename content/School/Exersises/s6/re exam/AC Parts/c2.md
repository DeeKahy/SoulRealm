# Presentation Notes – Computability & Reductions

## 1.  Computable vs. Computably-enumerable (c.e.)

| Concept | Definition | Machine | Halting? |
|---|---|---|---|
| **Decidable / Computable / Recursive** | ∃ halting DTM **accepting exactly L** | halts on **all** inputs in **t or r** | **Yes** |
| **c.e. / semi-decidable / recursively enumerable** | ∃ DTM **accepting exactly L** | **may loop** on w ∉ L | **No** |
- **AP** (“Does M **accept** w?”) – _yes_ only if the machine ends in the **accept** state.
- **HP** (“Does M **halt** on w?”) – _yes_ if the machine ends in **either accept or reject**, i.e., it just has to **stop**.
- 
- **Key fact**: Decidable ⇒ c.e.  
- **Characterisation**:  
  L decidable  ⇔  L and complement both c.e. (“complement lemma”).

## 2.  Example Languages

-  **HP** = {⟨⌜M⌝,w⟩ | M **halts** on w} – c.e. but **not** decidable  
-  **AP** = {⟨⌜M⌝,w⟩ | M **accepts** w} – c.e. but **not** decidable  
-  **∅** and **Σ*** – decidable  
-  **π-zero problem** – decidable (but we do **not** know which DTM decides it).

## 3.  Reductions

**Definition**  
Language **A** *mapping-reduces* to **B** (write **A ≤m B**) if there exists a **computable** function  
  f : Σ₁* → Σ₂*  such that  
  w ∈ A  ⇔  f(w) ∈ B.


### Properties & Usage

-  **Transitivity**: A ≤m B and B ≤m C ⇒ A ≤m C.  
-  **Hardness transfer**: If A is undecidable and A ≤m B, then **B is undecidable**.  
-  **Recipe for proofs**  
  1.  Choose a known undecidable problem **A** (usually AP or HP).  
  2.  Construct f that maps instances of A to instances of B.  
  3.  Argue **correctness** and **computability** of f.

### Example 1 – Halting ⇒ Acceptance

Show **HP ≤m AP**.

-  Input: ⟨⌜M⌝,w⟩.  
-  Build M′ that on *any* input x  
  1. erases x, writes w,  
  2. simulates M on w,  
  3. if M halts, M′ **accepts** x.  
-  Then  
  M halts on w  ⇔  L(M′) = Σ*  ⇒  M′ accepts every string  ⇒  ⟨⌜M′⌝,ε⟩ ∈ AP.  
Hence f(⟨⌜M⌝,w⟩) = ⟨⌜M′⌝,ε⟩ is the required reduction.

### Example 2 – Emptiness Problem

**NEP** = {⌜M⌝ | L(M) ≠ ∅} is undecidable.

-  Reduce **AP ≤m NEP**.  
  –  On input ⟨⌜M⌝,w⟩ build M_w that  
    1. erases its own input,  
    2. writes w,  
    3. simulates M on w,  
    4. accepts if M accepts.  
  –  L(M_w) = ∅  ⇔  M does **not** accept w.  
  –  Hence ⟨⌜M⌝,w⟩ ∈ AP  ⇔  ⌜M_w⌝ ∈ NEP.

## 4.  Rice’s Theorem (One-liner)

Any non-trivial semantic property of c.e. languages is **undecidable**.

-  “Semantic” = depends only on the *language* L(M), not on syntax.  
-  “Non-trivial” = neither empty nor all machines satisfy the property.

### Typical Applications

| Property | Undecidable by Rice |
|---|---|
| L(M) = ∅ | yes |
| L(M) finite | yes |
| L(M) contains at least one palindrome | yes |
| L(M) = Σ* | yes |
| M has 5 states | no (syntactic) |

## 5.  Quick Checklist for Presentation

-  Use the **complement lemma** to show decidability.  
-  Use **reductions** to show undecidability—always state the *source* problem and the *computable* map.  
-  Quote **Rice** when the question is about *any* semantic property.

## 6.  One-slide “Cheat Sheet”

```
Decidable   ⇔   c.e. + complement c.e.
Reduction   :   A ≤m B, A undecidable ⇒ B undecidable
Rice        :   Any non-trivial semantic property of programs → undecidable
```
